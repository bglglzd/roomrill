## Reconciliation measurement

On an Intel Core i7-12700K, 20 logical CPUs, Windows, CPython 3.11.15 and SQLite 3.53.1, 200 full `Engine.reconcile` calls with 20 active light leases across a two-room ledger took median **8.10 ms**, p95 **9.09 ms**, maximum **12.81 ms**. The timed region includes snapshot validation, encoding and SQLite commit. No network or concurrency was in that region. [Raw samples, workload and source hashes](results/reconciliation-v1.json).

```sh
python scripts/benchmark.py --output reports/new-benchmark
```

This measures a small retained-history ledger on one machine. Snapshot cost grows with stored history. No long-running installation, real-time, load-capacity or hardware-latency claim follows from it.

## Interface and model boundaries

Actual-engine browser journeys exercise priority, manual changes, expiry, disconnected observation, reconnect, delayed delivery and session refresh. Separate labelled UI fixtures test rendering/error boundaries; they are not substituted for engine results. Local and recorded modes are checked separately. Static recordings are generated by the real engine and cannot mutate state.

Live local draft verification used Qwen3-4B Q4_K_M with llama.cpp build 12211, four CPU threads and a 4,096-token context. A complete request produced a typed draft while the SQLite file and lease count stayed unchanged; UI confirmation remained separate. This is compatibility evidence for that mode, not an extraction accuracy benchmark. Earlier development calls returned invalid shape or requested clarification; validation refused them without changing the ledger. JSON-schema generation and preserving schema property order improved that development example, without changing scenario labels.

Synthetic HTTP tests cover the worker, redirects, response bounds, strict drafts and owned deadline cleanup. Those fixtures are not live inference. No external paid provider, Home Assistant integration, physical device, screen-reader study or power-loss recovery has been verified. SQLite-local version/fence guarantees must not be generalized to ordinary hardware service calls.
